## Wniosek dla właściciela

W najbliższych miesiącach największy zwrot z ograniczonego czasu dają: **audyt publicznego image-cache, domknięcie prawnej blokady źródeł na poziomie transportu oraz poprawa pokrycia metadanych z już używanych źródeł**. Nie rekomenduję teraz kolejnej dużej integracji marketplace ani nowych funkcji handlowych.

BookFlip ma już szeroki zestaw źródeł i rozbudowany przepływ ISBN → wydanie → kolejka ręcznej decyzji. Najpierw trzeba zabezpieczyć to, co już działa, i zmierzyć, gdzie faktycznie giną rozpoznania. Nowy antykwariat jest wart kontaktu, ale nie warto pisać adaptera bez zgody na automatyczny odczyt.

- kopie SQLite, diagnostykę, testy, skan kodu aparatem telefonu i paczkę offline.

Nie proponuję ponownego wdrażania powyższych elementów. W szczególności nie proponuję nowego „systemu serii”, kolejnej kolejki, ogólnej integracji ISBN, obsługi telefonu ani mechanizmu backupu — te obszary już istnieją. Należy poprawiać konkretne braki, nie budować ich drugi raz.

### C2. AbeBooks — oficjalne API, ale niszowy rynek międzynarodowy

- **Używane polskie wydania:** potwierdzone w indeksowanym wyniku wyszukiwania Warhammer Fantasy Role Play. Wynik pokazał polską „Szara eminencja: Kampania Wewnętrzny Wróg — edycja polska”, Games Workshop, 1997, ISBN 9788386572373, w dwóch ofertach używanych. Jedna oferta była z Czech, druga z Niemiec. - **Ryzyka:** duplikaty rekordów z połączonych katalogów, różnice w opisie wydania, błędne lub niepełne dane o języku i serii. Sam rekord bibliograficzny nie jest ofertą rynkową.
- **Adapter:** 2/5, bo można sprawdzić zgodność odpowiedzi z istniejącym parserem MARC; rzeczywisty przyrost pokrycia nie został jeszcze zmierzony.
- **Decyzja:** WARTA TESTU jako fallback metadanych po negatywnym wyniku institutions, nie jako nowy skaner ofert.

**Wniosek C:** Authentic jest najlepszym polskim kandydatem do kontaktu; AbeBooks ma oficjalne API, ale słabe dopasowanie do lokalnego rynku; Amicus na razie odrzucić; BN networks przetestować jako metadane. Nie znalazłem piątego nowego źródła, które dawałoby lepszy stosunek kompletności, legalności i kosztu.

## E. Eksperyment: czy BN /networks realnie zwiększa kompletność ISBN?

**Hipoteza:** dla próbki 50 polskich wydań, których nie znalazł obecny endpoint BN institutions, endpoint BN networks zwróci co najmniej 10% dodatkowych dokładnych rekordów ISBN, a odsetek konfliktów ISBN/tytuł/język pozostanie poniżej 1%.

**Metoda**
1. Na kopii bazy wybrać 50 zadań, w których ISBN jest poprawny, ale BN institutions zwróciło not_found.
2. Dla każdego ISBN wykonać pojedyncze zapytanie do BN networks z filtrem rodzaju materiału książka i limitem 10.
3. Porównać ISBN, tytuł, autora, wydawcę, język i pola serii z istniejącym rekordem oraz danymi wydania.
4. Wykorzystać obecny parser MARC, jeśli struktura odpowiedzi jest zgodna; nie dodawać zależności.
5. Nie importować wyników automatycznie. Zapisać próbkę, rozbieżności i czas odpowiedzi.

**Próg decyzji**
- pozytywny: co najmniej 5/50 dodatkowych dokładnych rekordów i mniej niż 1% konfliktów;
- negatywny: mniej niż 2/50 dokładnych rekordów albo więcej niż 1% konfliktów;
- 2–4 dodatkowe rekordy: rozszerzyć próbkę do 100.

To test wykorzystuje legalnie udostępnione dane CC0 i istniejący mechanizm metadanych. Nie jest nowym skanem ofert ani powodem do automatycznego przypisywania wydań.

## F. Jeden najlepszy następny krok

**Najpierw audyt data/image-cache w publicznym repozytorium bookflip/main.** To nie jest funkcja użytkowa, ale obecnie ma największy potencjalny koszt błędu: obrazy i ich pochodzenie są utrwalone publicznie, a cache nie jest wykluczony z Git.

### Specyfikacja dla Claude Code — materiał analityczny, nie automatyczne polecenie

1. Na lokalnej kopii repo zinwentaryzować 275 ścieżek data/image-cache, rozmiary, typy MIME z plików .type i powiązane moduły.
2. Z właścicielem ustalić pochodzenie reprezentatywnych próbek: okładki, zdjęcia ofert, zdjęcia egzemplarzy lub inne obrazy. Nie zakładać, że są to wyłącznie okładki.
3. Sprawdzić, czy katalog cache jest wyprowadzany z lokalizacji bazy i czy może wskazać katalog repozytorium przy niestandardowej konfiguracji BOOKFLIP_CATALOG_DB.
4. Jeżeli cache jest odtwarzalny i nie zawiera danych, które muszą pozostać, przygotować osobną propozycję: wykluczenie data/image-cache z Git i usunięcie go z bieżącego drzewa.
5. Osobno opisać, czy usuwanie z historii Git jest potrzebne. Nie przepisywać historii bez osobnej zgody.

### Kryteria akceptacji

- potwierdzone pochodzenie i klasyfikacja payloadów;
- brak śledzonych plików cache po zatwierdzonej zmianie;
- cache jest zapisywany w katalogu danych użytkownika, poza repo;
- świeży klon i test na pustej bazie nie powodują pojawienia się plików cache w git status;
- żadna baza, historia ofert ani ręczne decyzje nie są modyfikowane;
- nie wykonano force-push ani przepisywania historii bez osobnej zgody.

### Plan testów

- test jednostkowy lokalizacji cache w katalogu tymczasowym;
- git ls-files data/image-cache;
- git check-ignore dla przykładowego pliku;
- uruchomienie aplikacji na izolowanej bazie;
- npm run verify;
- porównanie git status przed i po uruchomieniu.

**Warunek przerwania:** jeśli nie da się ustalić pochodzenia obrazów albo ich bezpiecznego usunięcia, zatrzymać się i przedstawić właścicielowi listę plików oraz ryzyk. Nie usuwać niczego automatycznie.

Po tym audycie następnym małym krokiem powinno być B2 — prawna blokada transportu. Dopiero potem warto wracać do adaptera Authentic.

## G. Czego nie robić teraz

1. **Nie dodawać kolejnego adaptera bez zgody i potwierdzonej podstawy dostępu.** Authentic wymaga kontaktu; Amicus ma ochronę botów; AbeBooks wymaga oficjalnego programu i klucza API.
2. **Nie obchodzić CAPTCHA, 403, ochrony botów ani robots.txt.** Allegro, OLX i Dedalus pozostają bez legalnego dostępu; Empikowy endpoint GraphQL nie jest dozwoloną drogą do ISBN.
3. **Nie reimplementować źródeł już obecnych w BookFlip.** Skupszop, Bookway, Conroy, BlackBooks, Szarlatan, Gelber, Copernicus, Insignis i pozostałe wymienione adaptery wymagają pomiaru jakości, nie drugiego adaptera.
4. **Nie rozwijać teraz funkcji kolekcjonerskich, chmury, kont, nowych alertów, snajpera ani rozliczania zysku.** Część podobnych mechanizmów jest już opisana w repo, ale bieżący zakres właściciela stawia skaner, katalog i weryfikację przed rozbudową handlu.
5. **Nie usuwać image-cache ani nie przepisywać historii Git przed audytem.** Najpierw ustalić pochodzenie i odtwarzalność.
6. **Nie scalać różnych ISBN tylko na podstawie tytułu.** Dotyczy to szczególnie reedycji, e-booków i wydań z różną oprawą.
7. **Nie traktować rzadkości ani ceny katalogowej wydawcy jako dowodu rentowności.** Do takiego wniosku potrzebne są porównywalne transakcje, stan egzemplarza, koszt dostawy i czas sprzedaży.
8. **Nie uruchamiać Claude Code na drzewie scanlive jako na aktualnym kodzie produktu.** scanlive jest miejscem publikacji raportów; aktualny kod do weryfikacji znajduje się w karno13/bookflip.

**Odpowiedź na pytanie o ograniczony czas:** najpierw zabezpieczyć repozytorium i egzekwowanie legalnych źródeł, potem zmierzyć przyrost metadanych z BN networks. Nowy antykwariat wdrażać dopiero po uzyskaniu zgody. To poprawi bezpieczeństwo, kompletność identyfikacji i jakość decyzji bez dokładania kolejnej warstwy technologicznej.
